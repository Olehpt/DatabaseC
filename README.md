# DatabaseC

HTTP-сервер табличной базы данных без связей между таблицами. Порт: `18080`.
Каждая база хранится в одном `<имя>.bin` в рабочем каталоге процесса и загружается
при запуске. Изменения сохраняются сразу. Запускайте один сервер на каталог хранения.

## Типы данных

| Тип API | C++ | Допустимые значения JSON |
| --- | --- | --- |
| `integer` | `int32_t` | Целое от −2147483648 до 2147483647; дробные числа и boolean отклоняются |
| `real` | `double` | Конечное число, включая целые |
| `char` | `char` | Строка ровно из одного байта, включая `"\u0000"`; многобайтовый символ вроде `Ж` не подходит |
| `string` | `std::string` | Строка, включая пустую; UTF-8 и встроенные нулевые байты сохраняются |
| `complex` | `std::complex<double>` | Объект `{"real": 1.5, "imag": -2.0}`; обе части — конечные числа |

`null` не поддерживается. Порядок значений в строке совпадает с порядком колонок.
Индексы строк начинаются с нуля; после удаления последующие индексы сдвигаются.
Индекс не является постоянным идентификатором записи.

## Запросы

В таблице `D` — имя базы, `T` — имя таблицы, `C` — имя колонки, `I` — индекс строки.
Тела запросов — JSON, кроме импорта. Имена в URL необходимо кодировать.

| Метод | Путь | Тело / результат |
| --- | --- | --- |
| GET | `/databases` | `{"databases": [...]}` |
| POST | `/databases/D` | Создать пустую базу |
| DELETE | `/databases/D` | Удалить базу и файл |
| GET | `/databases/D/export` | Скачать всю базу как `application/octet-stream` |
| POST | `/databases/D/import` | Создать новую базу из бинарного тела; существующая база → 409 |
| PUT | `/databases/D/import` | Заменить существующую базу из бинарного тела; отсутствующая → 404 |
| GET | `/databases/D/tables` | `{"tables": [{"name": "..."}]}` |
| POST | `/databases/D/tables/T` | Создать пустую таблицу |
| GET | `/databases/D/tables/T` | Имя, колонки и `row_count` |
| PUT | `/databases/D/tables/T` | `{"name": "новое имя"}` — переименовать таблицу |
| DELETE | `/databases/D/tables/T` | Удалить таблицу |
| GET | `/databases/D/tables/T/columns` | Список колонок с именами и типами |
| POST | `/databases/D/tables/T/columns` | `{"name": "age", "type": "integer", "default": 0}` |
| PUT | `/databases/D/tables/T/columns/C` | `{"name": "новое имя"}` — переименовать колонку |
| DELETE | `/databases/D/tables/T/columns/C` | Удалить колонку и её значения во всех строках |
| GET | `/databases/D/tables/T/rows` | `{"rows": [{"index": 0, "values": [...]}]}` |
| POST | `/databases/D/tables/T/rows` | `{"values": [1, 2.5, "A", "текст"]}` — добавить строку |
| DELETE | `/databases/D/tables/T/rows` | Очистить таблицу, сохранив колонки |
| GET | `/databases/D/tables/T/rows/I` | Одна строка: `index`, `values` |
| PUT | `/databases/D/tables/T/rows/I` | `{"values": [...]}` — заменить всю строку |
| PATCH | `/databases/D/tables/T/rows/I` | `{"values": {"age": 25}}` — обновить перечисленные колонки |
| DELETE | `/databases/D/tables/T/rows/I` | Удалить строку |

При добавлении колонки `default` необязателен: существующие строки получают
`0`, `0.0`, `"\u0000"`, `""` или `{"real": 0.0, "imag": 0.0}` соответственно типу. Если `default` передан,
он проверяется по типу. Тип существующей колонки не изменяется запросом переименования.
GET возвращает пустые коллекции как `[]`.
Создание возвращает 201, остальные успешные операции — 200; неверные данные — 400,
отсутствующие объекты — 404, дубликаты — 409, слишком большой импорт — 413,
ошибка сохранения — 500. Ошибки возвращают JSON с полем `message`.

## Импорт и экспорт

```powershell
curl.exe http://localhost:18080/databases/demo/export --output demo.bin
curl.exe -X POST http://localhost:18080/databases/copy/import -H "Content-Type: application/octet-stream" --data-binary "@demo.bin"
curl.exe -X PUT http://localhost:18080/databases/copy/import -H "Content-Type: application/octet-stream" --data-binary "@demo.bin"
```

Импорт принимает сам файл в теле HTTP, без JSON, base64 и multipart-обёртки.
Имя целевой базы задаётся URL; файл содержит все таблицы, колонки и строки.
Валидация выполняется полностью до сохранения. При ошибке импорта или записи
существующая база в памяти и на диске остаётся прежней. Сохранение выполняется
через соседний временный файл и замену целевого файла; запросы сериализованы mutex.

Новый формат: четыре байта `DBC1`, версия `uint32 = 1`, количество таблиц `uint32`,
затем таблицы. Таблица: имя, количество колонок, пары имя/тип, количество строк,
значения строк в порядке колонок. Строки кодируются длиной `uint32` и байтами;
числа — little-endian, `real` — IEEE 754 binary64, `char` — один байт.
Коды типов: 0 = integer, 1 = real, 2 = char, 3 = string.
Тип `complex` имеет код 4 и занимает 16 байт: сначала действительная,
затем мнимая часть, каждая — little-endian IEEE 754 binary64. Старые коды типов
и заголовок версии 1 сохранены; предыдущий сервер отклоняет файлы с типом 4.
Объект complex в JSON должен содержать ровно два поля `real` и `imag`;
строки вроде `"1+2i"`, массивы, boolean, `null`, NaN и бесконечности отклоняются.

Пример создания колонки и записи:

```json
{"name": "z", "type": "complex", "default": {"real": 0, "imag": 0}}
```

```json
{"values": [{"real": 1.5, "imag": -2.0}]}
```

Для частичного обновления строки: `{"values": {"z": {"real": 3, "imag": 4}}}`.
Обновление complex заменяет обе части числа одновременно.
Прежние файлы без заголовка читаются; следующее сохранение переводит их в новый формат.
Старый сервер не умеет читать новый формат.

Ограничения: база — 64 MiB, строковое значение — 16 MiB, имя таблицы/колонки —
1024 байта, имя базы — 128 байт, до 10000 таблиц и колонок на таблицу,
до 1000000 записей и 1000000 значений суммарно на базу.
Имена баз проверяются на разделители путей, управляющие символы и зарезервированные
Windows-имена. Неизвестные версии/типы, дубликаты, неконечные real, обрезанные файлы
и лишние байты после базы отклоняются.

## Сборка и проверка

Crow и Boost уже находятся в `external`. Нужны CMake и компилятор C++20.
Пресеты Visual Studio используют Ninja и требуют окружение компилятора MSVC.
Для MinGW:

```powershell
cmake -S . -B out/build/verification -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build out/build/verification -j 4
ctest --test-dir out/build/verification --output-on-failure
python tests/api_test.py out/build/verification/DatabaseC.exe
```

HTTP-тестам нужен Python 3 и свободный порт 18080. Они запускают отдельный сервер
в временном каталоге и проверяют CRUD, типы, параллельные запросы, импорт/экспорт,
ошибки записи и перезапуск, не затрагивая пользовательские базы.

Границы реализации: нет SQL, связей, индексов поиска, фильтрации, сортировки,
пагинации, пользовательских транзакций и преобразования типов существующих колонок.
